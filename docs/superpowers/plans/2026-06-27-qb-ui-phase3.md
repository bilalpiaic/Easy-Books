# QB Online UI Redesign — Phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate all remaining ~155 files (115 page files + 40 component files) from hardcoded gold/cream hex values to QB CSS custom-property tokens, completing the full QB Online 2024 UI redesign.

**Architecture:** Same mechanical approach as Phase 2 — standard sed block per task group, manual StatusBadge replacement for any remaining `statusColors`/`STATUS_TONE` dicts, build verification after each task. No logic changes anywhere.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind CSS v4, lucide-react

## Global Constraints

- **Zero logic changes.** Only `className` strings and `statusColors`/`STATUS_TONE` dict removals change. Every API call, state variable, handler, and conditional remains untouched.
- **Zero backend changes.**
- **`npm run build` must pass** after every task before committing.
- **`StatusBadge` from `@/components/StatusBadge`** replaces every `statusColors`/`STATUS_TONE` dict. Import it and use `<StatusBadge status={x} />`.
- **`PRA_STATUS_TONE` in `invoices/[id]/page.tsx` must NOT be removed** — it handles PRA-specific portal statuses (`not_required`, `submitted`, `failed`) and is intentionally separate.
- **`bg-[#1a1814]` in `invoices/page.tsx` PRA banner must NOT be changed** — high-contrast intentional UI element.
- **`#f0ede6` and `#faf8f4`** are lighter interactive-hover tints in vendors/customers pages — do NOT replace them if encountered.
- **After every sed pass, grep for residuals:** `#ede9e2`, `#b8943f`, `#f6f3ee`, `#faf6ec`, `#a07c3[0-9]`, `text-black/[0-9]`, `font-serif`.
- All tasks run from `/home/mbilal71/projects/Easy-Books` (repo root).
- Frontend commands run from `frontend/` subdirectory.
