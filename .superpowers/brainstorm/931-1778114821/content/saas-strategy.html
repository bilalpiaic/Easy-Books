Multi-Tenant SaaS Strategy

Switching to SaaS requires a fundamental change in how we handle data and users. Which isolation strategy do you prefer?

A

Shared Database (Column-based)

All tenants share the same tables. Every row has a tenant_id.

  • Pros: Easy to manage, low cost, simple scaling.
  • Cons: Risk of data leakage if queries aren't scoped correctly.
B

Schema-based Isolation

Each tenant gets their own schema/database (e.g., PostgreSQL schemas).

  • Pros: Stronger security, easier backups per tenant.
  • Cons: More complex migrations, higher infra overhead.

Recommendation

For a startup SaaS FMS, Option A (Shared Database) is usually the best starting point for development speed and cost-efficiency, provided we use robust row-level security or global query filters.
